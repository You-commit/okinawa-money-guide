- Date: 2026-09-16
- Status: **実行計画・ユーザー承認方針反映**
- Baseline Git SHA: `0d7aefa287bffbdad95bd096cecfa91eb83ea565`

## 1. 現状診断

### 1.1 既に実装済みの技術SEO

現行実装には以下がある。

- 5シミュレーター、`/knowledge`、`/about`、`/trust` を含む9正式URL
- route別title
- route別description
- canonical
- `index, follow`
- OGP / X metadata
- route別静的HTMLファイル
- 404.html / noindex
- robots.txt
- sitemap.xml

したがって、現時点の課題は「index可能な技術基盤が存在しないこと」ではない。

### 1.2 現在の弱点

2026-09-16時点の公開Web検索では、OMGのシミュレーターURLが検索結果として十分確認できない。

考えられる改善対象は以下。

- ドメイン・ページの公開からの時間
- Google側のクロール／インデックス状況の未確認
- シミュレーターページの可視解説コンテンツ量
- 記事コンテンツ不足によるテーマ権威性・内部リンク不足
- `/knowledge` 内の多くのテーマが「準備中」
- シミュレーターへ向けた検索意図別記事が不足
- 初期HTTP HTMLのheadはroute別だが、本文はReact実行後に描画される構造

Google Search Consoleでの実測を行わない限り、「未インデックス」「インデックス済みだが順位が低い」「クロール済み・未登録」等を断定しない。

## 2. SEO強化の原則

SEOのために利用体験を壊さない。

- シミュレーターを使う前に長大な文章を読ませない。
- 検索キーワードを不自然に詰め込まない。
- 実際にページに存在しない内容をmetaや構造化データへ記載しない。
- 金融YMYL領域として一次情報・基準日・更新履歴を重視する。
- 「沖縄」を装飾キーワードとして連呼せず、地域固有の判断課題で差別化する。

## 3. シミュレーターSEO強化

### 3.1 ページ内解説ブロック

各シミュレーターの主操作を邪魔しない位置に、以下の共通構造を追加する。

1. このシミュレーターで分かること
2. 計算結果の見方
3. 計算に含まれないもの
4. 制度・金融商品の確認ポイント
5. 関連する知識記事
6. 関連シミュレーター
7. 情報源・基準日

### 3.2 シミュレーター別検索意図

#### 軍用地

主検索意図：
- 軍用地 利回り 計算
- 軍用地 倍率 利回り
- 軍用地 回収年数
- 沖縄 軍用地 投資

#### 住宅ローン

主検索意図：
- 住宅ローン シミュレーション
- 沖縄 住宅ローン
- 元利均等 元金均等 比較
- 住宅ローン 総返済額

#### NISA

主検索意図：
- NISA シミュレーション
- NISA 積立 シミュレーション
- NISA 将来額
- NISA 毎月いくら

#### iDeCo

主検索意図：
- iDeCo 節税 シミュレーション
- iDeCo 税金 いくら減る
- iDeCo 掛金 上限

#### 課税所得

主検索意図：
- 課税所得 計算
- 所得税率 計算
- 給与 課税所得

キーワードは記事設計の参考とし、不自然な反復は行わない。

### 3.3 初期HTML本文の強化

現状はbuild時にroute別SEO headを生成している一方、`#root` の本文はReact実行後に描画される。

実装候補：

- React表示内容と一致するroute別の静的導入本文をbuild時にも出力する
- JavaScript無効時でもページの目的・H1・主要内部リンクを理解できる構造にする
- React実行後の表示と意味的に一致させ、検索エンジン向けだけの隠し文章を作らない

実装前に、現行Cloudflare Pagesのdeep-link HTTPレスポンスとレンダリング後DOMを再監査する。

## 4. 記事基盤

### 4.1 URL方針

推奨：`/knowledge/<slug>`

理由：
- 既存の`/knowledge`をハブとして活かせる
- トピッククラスターが分かりやすい
- 記事とシミュレーターを同一サイト構造で接続しやすい

最終URL命名は実装前に重複・将来拡張性を確認する。

### 4.2 記事テンプレート

全記事で原則以下を持つ。

- H1
- 要点
- この記事で分かること
- 本文
- 沖縄固有の確認点（該当時のみ）
- シミュレーター導線
- 関連記事
- 一次情報・参考情報
- 基準日／更新日
- 広告・提携がある場合の適切な表示

### 4.3 初期記事ロードマップ

第1クラスター：住宅ローン

- 沖縄で住宅ローンを比較するときの確認項目
- 変動金利と固定金利の基本
- 元利均等と元金均等の違い
- 保証料・融資手数料・団信の見方
- 沖縄県内金融機関の商品比較（基準日付き）

第2クラスター：NISA

- NISA制度の基本
- つみたて投資枠と成長投資枠
- 毎月積立額から将来額を考える方法
- 証券口座を選ぶときの確認項目
- 沖縄県民がNISAを始める際の実務導線

第3クラスター：iDeCo

- iDeCoの加入区分
- 掛金上限
- 節税効果の見方
- 2026年12月1日以降の制度境界

第4クラスター：軍用地

- 倍率とは何か
- 倍率と利回りの違い
- 共有持分の確認
- 年間借地料と費用
- 回収期間の考え方

第5クラスター：保険・沖縄生活

- 沖縄の自動車保険で確認したい補償
- 台風・風災と火災保険
- 車を持つ家計の固定費

## 5. 内部リンク設計

基本構造：

`Home → Knowledge Hub → 詳細記事 → Simulator → 関連記事／必要な場合のみ関連サービス`

逆方向も作る。

`Simulator → 計算結果 → 解説記事 → 制度一次情報`

広告リンクを内部リンクの代替にしない。

## 6. 構造化データ

採用候補：

- `WebSite`：既存維持
- `WebPage`：ページ種別に応じて検討
- `Article`：詳細記事に、実際に表示している事実のみ
- `BreadcrumbList`：パンくず導入後に追加

原則不採用：

- 架空のRating / Review
- 実在しないAuthor資格
- 根拠のないAward
- FAQ表示が存在しないページへのFAQ schema

## 7. Search Console運用

接続後に以下を実行する。

1. プロパティ確認
2. `sitemap.xml` 送信状況確認
3. 5シミュレーターのURL検査
4. `/knowledge` のURL検査
5. 新規記事のURL検査
6. 「クロール済み・インデックス未登録」等の理由確認
7. 重要ページのみインデックス登録をリクエスト
8. 2〜4週間単位で表示回数・クリック・クエリを観測

インデックス登録リクエストは順位保証ではない。
